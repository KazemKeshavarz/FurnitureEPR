# FurnitureEPR

سامانه مدیریت سفارش و گردش تولید کارگاه مبلمان و محصولات خواب؛ با تمرکز بر ثبت سفارش، پیگیری مراحل تولید، کنترل کیفیت و تحویل به مشتری.

## وضعیت فعلی

- بک‌اند ASP.NET Core / .NET 10 با معماری لایه‌ای و CQRS.
- فرانت‌اند Angular 20 و Angular Material، فارسی و RTL.
- بررسی خودکار ساخت بک‌اند و فرانت‌اند در GitHub Actions فعال است.
- آخرین بررسی کامل بک‌اند در شاخهٔ کاری موفق بوده است؛ پس از تغییرات امنیتی و ارتقای وابستگی‌ها، CI باید دوباره موفق شود. CI به‌تنهایی جایگزین آزمون انتهابه‌انتها روی محیط عملیاتی نیست.

## محدوده سامانه

### داخل محدوده
- تعریف مشتری، دسته‌بندی محصول، محصول و اجزای تشکیل‌دهنده محصول.
- تعیین تعداد پیش‌فرض اجزای محصول و امکان تغییر تعداد در سفارش.
- ثبت سفارش، مبلغ کل، تخفیف و مبلغ نهایی به ریال.
- تعریف گردش‌کار و نسخه‌بندی مراحل و مسیرهای مجاز.
- اجرای گردش‌کار سفارش، مشاهده تاریخچه، کنترل کیفیت و صف کارهای تولید.
- تعریف کاربران، نقش‌ها و دسترسی‌ها.

### خارج از محدوده فعلی
- حسابداری و امور مالی، انبارداری و کنترل موجودی، حقوق و دستمزد و درگاه پرداخت.
- اجرای واقعی مراحل موازی تولید؛ مدل فعلی اجرای ترتیبی دارد و برای موازی‌سازی به مدل Branch/WorkItem نیاز است.

## اجزای مخزن

- `src/`: پروژه‌های بک‌اند .NET.
- `tests/`: تست‌های بک‌اند.
- `frontend/FurnitureEPR.Angular/`: پنل وب Angular.
- `docs/architecture/workflow-runtime.md`: شرح معماری و محدودیت‌های اجرای گردش‌کار.
- `.github/workflows/`: بررسی خودکار ساخت و تست.

## اجرای بک‌اند

پیش‌نیاز: .NET SDK 10.0.402 یا جدیدتر از شاخهٔ 10، SQL Server و پیکربندی امن محیط اجرا. **پروژه هنوز migration اولیهٔ EF Core ندارد**؛ ایجاد/به‌روزرسانی schema پایگاه داده باید قبل از اجرای کامل سامانه آماده شود.

```bash
dotnet restore FurnitureEPR.sln
dotnet build src/FurnitureEPR.Presentation/FurnitureEPR.Presentation.csproj --configuration Release
dotnet test tests/FurnitureEPR.Model.Tests/FurnitureEPR.Model.Tests.csproj --configuration Release
```

### تنظیمات امن بک‌اند

پیش از اجرا، کلید JWT واقعی و تصادفی با حداقل 32 کاراکتر را از User Secrets یا متغیر محیطی `Jwt__Key` تنظیم کنید. مقدار placeholder موجود در `appsettings.json` عمداً توسط برنامه رد می‌شود. برای ساخت اولین مدیر، `IdentitySeed__Enabled=true` و مقادیر امن `IdentitySeed__AdminUserName`، `IdentitySeed__AdminEmail` و `IdentitySeed__AdminPassword` را فقط از متغیرهای محیطی یا Secret Store فراهم کنید؛ رمز مدیر را در مخزن ثبت نکنید. همهٔ endpointها به‌صورت پیش‌فرض نیازمند احراز هویت هستند؛ `/api/auth/login` و `/api/health` عمومی‌اند. تعریف گردش‌کار و اتصال آن به دسته‌بندی به مجوز `workflow.manage` نیاز دارد.

## اجرای فرانت‌اند

پیش‌نیاز: Node.js 22.

```bash
cd frontend/FurnitureEPR.Angular
npm install
npm start
```

آدرس API در تنظیمات محیطی فرانت‌اند تعیین می‌شود. برای اجرای کامل، بک‌اند و پایگاه داده نیز باید در دسترس باشند.

## مسیرهای اصلی API

پیشوند معمول endpointها `/api` است.

| قابلیت | مسیرهای نمونه |
|---|---|
| مشتریان | `GET/POST /api/customers` |
| دسته‌بندی‌ها | `GET/POST /api/categories` |
| محصولات | `GET/POST /api/products` |
| اجزا | `GET/POST /api/components` |
| اجزای محصول | `POST /api/products/{productId}/components` |
| سفارش‌ها | `GET/POST /api/orders` |
| نهایی‌کردن سفارش | `POST /api/orders/{id}/finalize` |
| تعریف گردش‌کار | `/api/workflows` و زیرمسیرهای نسخه، مرحله و انتقال |
| کارهای تولید | `GET /api/orders/production/tasks` |
| کنترل کیفیت | `POST /api/orders/{orderId}/workflow/{categoryId}/quality-control` |

برای جزئیات دقیق قراردادهای درخواست و پاسخ، به Controllerها و DTOهای متناظر در بک‌اند مراجعه کنید.

## وضعیت و کارهای باقی‌مانده

موفقیت CI یعنی کد در محیط GitHub Actions نصب/ساخت شده و تست‌های تعریف‌شده در workflow بک‌اند موفق بوده‌اند. این وضعیت به معنی تأیید کامل تجربه کاربری یا تست یکپارچه همه سناریوهای کسب‌وکار نیست.

پیش از بهره‌برداری باید دست‌کم موارد زیر تکمیل و تأیید شوند:
1. اجرای end-to-end ثبت سفارش از ابتدا تا انتهای تولید و تحویل با پایگاه داده واقعی.
2. تست یکپارچهٔ سیاست احراز هویت پیش‌فرض، مجوز مدیریت گردش‌کار و مجوزهای QC/انتقال/تکمیل.
3. ایجاد و بازبینی migration اولیه، سپس اجرای آن و آزمون روی SQL Server محیط مقصد.
4. بررسی رابط کاربری روی موبایل با نقش‌های واقعی کاربران کارگاه.
5. افزودن تست‌های یکپارچه برای سفارش، انتقال مراحل، QC و تکمیل گردش‌کار.
6. مشخص‌کردن فرآیند واقعی کارگاه؛ اجرای موازی هنوز پشتیبانی نمی‌شود و نباید پیش از مدل‌سازی دقیق وعده داده شود.
7. تعیین CORS originهای محیط استقرار و اجرای آزمون نهایی روی دستگاه موبایل.

## CI

- Frontend CI: نصب وابستگی‌ها و اجرای `npm run build`.
- Backend CI: Restore، Build بک‌اند و اجرای پروژه تست `FurnitureEPR.Model.Tests`.

اجرای جاری را در بخش Actions مخزن GitHub ببینید.
