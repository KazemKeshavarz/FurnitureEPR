# FurnitureEPR

سامانه مدیریت سفارش و گردش تولید کارگاه مبلمان و محصولات خواب؛ با تمرکز بر ثبت سفارش، پیگیری مراحل تولید، کنترل کیفیت و تحویل به مشتری.

## وضعیت فعلی

- بک‌اند ASP.NET Core / .NET 10 با معماری لایه‌ای و CQRS.
- فرانت‌اند Angular 20 و Angular Material، فارسی و RTL.
- بررسی خودکار ساخت بک‌اند و فرانت‌اند در GitHub Actions فعال است.
- داشبورد گزارش‌گیری عملیاتی و APIهای گزارش سفارش، تولید، محصول و فعالیت کاربران اضافه شده‌اند.

## محدوده سامانه

### داخل محدوده
- تعریف مشتری، دسته‌بندی محصول، محصول و اجزای تشکیل‌دهنده محصول.
- تعیین تعداد پیش‌فرض اجزای محصول و امکان تغییر تعداد در سفارش.
- ثبت سفارش، مبلغ کل، تخفیف و مبلغ نهایی به ریال.
- تعریف گردش‌کار و نسخه‌بندی مراحل و مسیرهای مجاز.
- اجرای گردش‌کار سفارش، مشاهده تاریخچه، کنترل کیفیت و صف کارهای تولید.
- تعریف چند انبار، تخصیص تعداد هر قلم سفارش به یک یا چند انبار و مشاهده محل نگهداری محصول؛ این قابلیت فقط ردیابی محل است و شامل موجودی‌گردانی یا حسابداری انبار نیست.
- درخواست انتقال جزئی یا همه اقلام آماده بین سفارش‌های هم‌مشخصات، با تأیید مدیر، ثبت تاریخچه و ثبت وضعیت کسری سفارش مبدأ.
- تعریف کاربران، نقش‌ها و دسترسی‌ها.
- گزارش سفارش‌ها، وضعیت سفارش‌ها، عملکرد مراحل تولید، نتایج QC، محصولات و فعالیت ثبت‌شده کاربران.

### خارج از محدوده فعلی
- حسابداری و امور مالی، کنترل موجودی و عملیات کامل انبارداری، حقوق و دستمزد و درگاه پرداخت.
- اجرای واقعی مراحل موازی تولید؛ مدل فعلی اجرای ترتیبی دارد و برای موازی‌سازی به مدل Branch/WorkItem نیاز است.

## گزارش‌ها

صفحه گزارش‌ها از مسیر `/reports` و با مجوز `workflow.manage` در دسترس مدیر گردش‌کار است. بازه زمانی برای گزارش‌ها قابل انتخاب است و شامل این بخش‌هاست:

- خلاصه مدیریت: تعداد سفارش‌ها، مجموع مبالغ، تخفیف‌ها، مبلغ نهایی، وضعیت سفارش‌ها، مرحله فعلی سفارش‌های فعال و آخرین سفارش‌ها.
- سفارش‌ها: فهرست صفحه‌بندی‌شده همراه مشتری، وضعیت، تعداد اقلام و مبالغ.
- عملکرد تولید: تعداد گردش‌کارهای جاری در هر مرحله، تعداد ورودهای ثبت‌شده به مراحل و نتیجه‌های QC.
- محصولات: تعداد سفارش، مقدار درخواستی و مبلغ اقلام هر محصول.
- فعالیت کاربران: تعداد درخواست‌های ثبت‌شده در AuditLog و تعداد درخواست‌های موفق/ناموفق.

نکته‌های تفسیری:
- به دلیل نبود تاریخ تحویل تعهدشده در مدل سفارش، گزارش «تأخیر نسبت به موعد تحویل» هنوز قابل محاسبه نیست.
- AuditLog فعلی برای سنجش مستقیم بهره‌وری اپراتور کافی نیست؛ گزارش کاربران فعلاً فعالیت ثبت‌شده در سامانه را نشان می‌دهد.
- گزارش مالی این صفحه فقط جمع مبالغ ثبت‌شده روی سفارش است و ماژول حسابداری، دریافت/پرداخت یا سود و زیان محسوب نمی‌شود.
- گزارش تولید بر اساس گردش‌کارها و تاریخچه ثبت‌شده است؛ تعداد عبور از مرحله معادل مدت‌زمان واقعی انجام کار نیست.

### API گزارش‌ها

| قابلیت | مسیر |
|---|---|
| خلاصه داشبورد | `GET /api/reports/summary` |
| گزارش سفارش‌ها | `GET /api/reports/orders` |
| گزارش مراحل تولید و QC | `GET /api/reports/production` |
| گزارش محصولات | `GET /api/reports/products` |
| فعالیت ثبت‌شده کاربران | `GET /api/reports/users` |

همه endpointهای گزارش در حال حاضر نیازمند مجوز `workflow.manage` هستند. پارامترهای `from` و `to` بازه تاریخ را تعیین می‌کنند؛ پیش‌فرض بازه ۳۰ روز اخیر است.

## اجرای بک‌اند

پیش‌نیاز: .NET SDK 10، SQL Server و پیکربندی امن محیط اجرا. Migrationها را با فرمان‌های مستندشده در `docs/database-migration.md` روی SQL Server اعمال کنید.

```bash
dotnet restore src/FurnitureEPR.Presentation/FurnitureEPR.Presentation.csproj
dotnet build src/FurnitureEPR.Presentation/FurnitureEPR.Presentation.csproj --configuration Release
dotnet test tests/FurnitureEPR.Model.Tests/FurnitureEPR.Model.Tests.csproj --configuration Release
```

## اجرای فرانت‌اند

پیش‌نیاز: Node.js 22.

```bash
cd frontend/FurnitureEPR.Angular
npm install
npm start
```

## وضعیت و کارهای باقی‌مانده

1. اجرای end-to-end ثبت سفارش تا تولید، انتقال، جبران کسری و تحویل با SQL Server واقعی.
2. اجرای migrationهای موجود و بازبینی schema نهایی روی SQL Server محیط مقصد.
3. بررسی گزارش‌ها با داده واقعی و کنترل سطح دسترسی نقش مدیر.
4. افزودن تاریخ تحویل تعهدشده برای گزارش تأخیر واقعی، در صورت تأیید فرآیند کسب‌وکار.
5. ثبت رویدادهای شروع/پایان هر مرحله و کاربر مسئول برای محاسبه زمان واقعی و گزارش دقیق بهره‌وری.
6. بررسی رابط کاربری روی موبایل با نقش‌های واقعی کاربران کارگاه.
7. اجرای موازی تولید هنوز پشتیبانی نمی‌شود و باید پس از مستندسازی فرآیند واقعی مدل‌سازی شود.

CI ساخت و تست جایگزین آزمون end-to-end روی محیط عملیاتی نیست.
