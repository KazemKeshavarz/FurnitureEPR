# Furniture EPR Angular

پنل وب فارسی و راست‌چین سامانه Furniture EPR با Angular و Angular Material.

## اجرا

```bash
npm install
npm start
```

برای ساخت نسخهٔ قابل انتشار:

```bash
npm run build
```

آدرس API در فایل‌های `src/environments` تنظیم می‌شود.

## فونت‌ها و آیکون‌های محلی

برای جلوگیری از وابستگی رابط کاربری به سرویس‌های Google، فونت فارسی Vazirmatn و فونت Material Icons از بسته‌های محلی npm تأمین می‌شوند. فایل‌های فونت هنگام نصب وابستگی‌ها در `node_modules` قرار می‌گیرند و Angular آن‌ها را در خروجی build به‌صورت asset محلی بسته‌بندی می‌کند؛ مرورگر در زمان اجرا نیازی به دسترسی به Google Fonts یا Google Material Icons ندارد.

پس از دریافت این تغییرات، در پوشه فرانت‌اند اجرا کنید:

```bash
npm install
npm run build
```

از اضافه‌کردن لینک Google Fonts یا بارگذاری آنلاین Material Icons به `src/index.html` خودداری کنید. استایل فونت‌ها در `src/styles.scss` مدیریت می‌شود.

## بخش‌های پیاده‌سازی‌شده در فرانت‌اند

- داشبورد اولیه
- ثبت و فهرست سفارش‌ها و مشاهده جزئیات سفارش
- فهرست کارهای تولید با نمایش تعداد قابل انجام در هر کار، عملیات مرحله، کنترل کیفیت و پایان فرآیند؛ شناسه‌های گردش‌کار مستقل در UI پنهان می‌مانند
- مدیریت مشتریان
- تعاریف اطلاعات پایه: دسته‌بندی‌ها، محصولات، اجزای محصول و تعداد پیش‌فرض اجزا
- مدیریت فرآیند تولید: دریافت فهرست و جزئیات فرآیندهای قبلی، انتخاب نسخه، ایجاد نسخه جدید، تعریف مراحل، نقش مسئول، کنترل کیفیت، مسیرها و انتشار/اتصال به دسته‌بندی
- مدیریت کاربران، نقش‌ها و دسترسی‌ها
- تعریف و فعال/غیرفعال‌سازی چند انبار در پنل مدیریت
- ثبت محل نگهداری هر قلم سفارش در یک یا چند انبار، با کنترل مجموع تعداد تخصیص‌یافته
- ثبت درخواست انتقال جزئی یا همه اقلام آماده بین سفارش‌ها، انتخاب خودکار اقلام مقصد هم‌مشخصات، و صفحه بررسی/تأیید یا رد درخواست توسط مدیر
- نمایش تاریخچه انتقال در جزئیات هر دو سفارش؛ انتخاب مبدأ فقط از اقلام دارای تخصیص انبار و گردش‌کار در مرحله `WAREHOUSE` انجام می‌شود
- با تأیید انتقال، کسری مبدأ به یک کار تولید مستقل تبدیل می‌شود؛ پس از پایان QC و فرآیند، تعداد جبرانی به انبار قبلی برمی‌گردد
- پوسته واکنش‌گرا با منوی قابل جمع‌شدن در موبایل
- کنترل نمایش عملیات تولید بر اساس مجوزهای انتقال، کنترل کیفیت و تکمیل
- تلاش مجدد برای نهایی‌سازی سفارش ثبت‌شده، بدون ساخت سفارش تکراری

## قرارداد ساختار کامپوننت‌ها

برای کامپوننت‌های صفحه‌ای، کد به سه فایل جدا تقسیم می‌شود:

- `*.component.ts`: منطق صفحه، فرم‌ها، سرویس‌ها و مدیریت رویدادها
- `*.component.html`: ساختار و نمایش HTML
- `*.component.scss`: استایل‌های مختص همان کامپوننت

هنگام افزودن صفحهٔ جدید، از `template` و `styles` درون‌خطی برای صفحات معمول استفاده نکنید؛ به‌جای آن `templateUrl` و `styleUrl` را به فایل‌های مجزا متصل کنید. این جداسازی نگهداری و بازبینی تغییرات را ساده‌تر می‌کند.

## ساختار

- `src/app/core`: احراز هویت، guardها و پوستهٔ اصلی
- `src/app/features`: صفحات و قابلیت‌های کسب‌وکار؛ قالب HTML و SCSS صفحات اصلی در فایل‌های جدا نگهداری می‌شوند
- `src/environments`: تنظیمات محیط و آدرس API

## نکات مهم

- صفحه‌های `/products` و `/categories` مستقیماً تب مربوط به خود را در تعاریف اطلاعات پایه باز می‌کنند.
- کنترل دسترسی رابط کاربری جایگزین کنترل دسترسی سمت API نیست. مسیرهای صفحه محصولات و دسته‌بندی در فرانت‌اند guard دارند؛ API ایجاد این اطلاعات هنوز به مجوز اختصاصی مدیریتی مجهز نشده و باید پیش از بهره‌برداری اصلاح شود.
- مسیر عملیات تولید بر اساس شناسه گردش‌کار است: `POST /api/orders/workflow/{workflowInstanceId}/transitions/{transitionId}`، `POST /api/orders/workflow/{workflowInstanceId}/quality-control` و `POST /api/orders/workflow/{workflowInstanceId}/complete`.
- مسیرهای API باید با نسخهٔ در حال اجرای بک‌اند هماهنگ باشند.
- ساخت فرانت‌اند در GitHub Actions اجرا می‌شود؛ نتیجه CI همان Commit را ملاک قرار دهید. آزمون دستی تجربه کاربری روی موبایل و نقش‌های واقعی همچنان باقی است.

### مدیریت فرآیندها و API

- صفحهٔ مدیریت فرآیند از `GET /api/workflows?page=1&pageSize=100` برای دریافت فهرست و از `GET /api/workflows/{workflowId}` برای بازیابی جزئیات استفاده می‌کند.
- جزئیات شامل نسخه‌ها، مراحل، مسیرها و دسته‌بندی‌های متصل است. نسخه منتشرشده فقط قابل مشاهده است؛ برای تغییرات باید نسخه جدید ساخته شود.
- مدیر می‌تواند نسخه پیش‌نویس را پس از بارگذاری مجدد صفحه انتخاب و تکمیل کند. شناسه‌های مراحل و مسیرها از API بازیابی می‌شوند و به حافظه موقت مرورگر وابسته نیستند.
- اتصال نسخه منتشرشده به دسته‌بندی، بدون انتشار دوباره نیز امکان‌پذیر است. اگر انتشار موفق اما اتصال ناموفق شود، همان نسخه قابل انتخاب و اتصال مجدد است.
- تمام endpointهای مدیریت فرآیند در بک‌اند با `workflow.manage` محافظت می‌شوند.
- صفحهٔ مدیریت انبارها از `GET/POST /api/warehouses` و endpointهای ویرایش/فعال‌سازی استفاده می‌کند.
- در جزئیات سفارش، تخصیص تعداد به چند انبار با `PUT /api/orders/items/{orderItemId}/warehouse-allocations` انجام می‌شود. تخصیص فقط در مرحلهٔ گردش‌کار با کد `WAREHOUSE` مجاز است؛ بنابراین کد مرحله انبار در تعریف فرآیند باید دقیقاً همین مقدار باشد.
- این قابلیت محل نگهداری را ثبت می‌کند و جایگزین سیستم کنترل موجودی یا گردش ورود و خروج کالا نیست. guard فرانت‌اند صرفاً تجربه کاربری را کنترل می‌کند و جایگزین مجوز سمت سرور نیست.
- اجرای مراحل موازی هنوز در مدل runtime پشتیبانی نمی‌شود؛ تعریف چند مسیر خروجی به معنی اجرای هم‌زمان شاخه‌ها نیست.
