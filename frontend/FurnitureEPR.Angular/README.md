# Furniture EPR Angular

پنل وب فارسی و راست‌چین سامانه Furniture EPR با Angular و Angular Material.

## اجرا

```bash
npm install
npm start
```

برای ساخت نسخهٔ قابل انتشار:

```bash
npm run build
```

آدرس API در فایل‌های `src/environments` تنظیم می‌شود.

## بخش‌های پیاده‌سازی‌شده در فرانت‌اند

- داشبورد اولیه
- ثبت و فهرست سفارش‌ها و مشاهده جزئیات سفارش
- فهرست کارهای تولید و عملیات مرحله، کنترل کیفیت و پایان فرآیند
- مدیریت مشتریان
- تعاریف اطلاعات پایه: دسته‌بندی‌ها، محصولات، اجزای محصول و تعداد پیش‌فرض اجزا
- مدیریت فرآیند تولید: ایجاد فرآیند و نسخه، تعریف مراحل، نقش مسئول، کنترل کیفیت، مسیرها و انتشار/اتصال به دسته‌بندی
- مدیریت کاربران، نقش‌ها و دسترسی‌ها
- پوسته واکنش‌گرا با منوی قابل جمع‌شدن در موبایل
- کنترل نمایش عملیات تولید بر اساس مجوزهای انتقال، کنترل کیفیت و تکمیل
- تلاش مجدد برای نهایی‌سازی سفارش ثبت‌شده، بدون ساخت سفارش تکراری

## قرارداد ساختار کامپوننت‌ها

برای کامپوننت‌های صفحه‌ای، کد به سه فایل جدا تقسیم می‌شود:

- `*.component.ts`: منطق صفحه، فرم‌ها، سرویس‌ها و مدیریت رویدادها
- `*.component.html`: ساختار و نمایش HTML
- `*.component.scss`: استایل‌های مختص همان کامپوننت

هنگام افزودن صفحهٔ جدید، از `template` و `styles` درون‌خطی برای صفحات معمول استفاده نکنید؛ به‌جای آن `templateUrl` و `styleUrl` را به فایل‌های مجزا متصل کنید. این جداسازی نگهداری و بازبینی تغییرات را ساده‌تر می‌کند.

## ساختار

- `src/app/core`: احراز هویت، guardها و پوستهٔ اصلی
- `src/app/features`: صفحات و قابلیت‌های کسب‌وکار؛ قالب HTML و SCSS صفحات اصلی در فایل‌های جدا نگهداری می‌شوند
- `src/environments`: تنظیمات محیط و آدرس API

## نکات مهم

- صفحه‌های `/products` و `/categories` مستقیماً تب مربوط به خود را در تعاریف اطلاعات پایه باز می‌کنند.
- کنترل دسترسی رابط کاربری جایگزین کنترل دسترسی سمت API نیست. مسیرهای صفحه محصولات و دسته‌بندی در فرانت‌اند guard دارند؛ API ایجاد این اطلاعات هنوز به مجوز اختصاصی مدیریتی مجهز نشده و باید پیش از بهره‌برداری اصلاح شود.
- مسیرهای API باید با نسخهٔ در حال اجرای بک‌اند هماهنگ باشند.
- ساخت فرانت‌اند در GitHub Actions اجرا می‌شود؛ نتیجه CI همان Commit را ملاک قرار دهید. آزمون دستی تجربه کاربری روی موبایل و نقش‌های واقعی همچنان باقی است.

### محدودیت فعلی مدیریت فرآیندها

- صفحهٔ مدیریت فرآیند از ایجاد فرآیند، ایجاد نسخه، افزودن مرحله و مسیر، انتشار نسخه و اتصال آن به دسته‌بندی پشتیبانی می‌کند.
- فرم‌ها با محدودیت‌های اعتبارسنجی بک‌اند هماهنگ شده‌اند؛ از جمله طول نام/کد، ترتیب غیرمنفی مرحله، جلوگیری از کد و ترتیب تکراری در همان نسخه، و جلوگیری از مسیر خودارجاع یا مسیر تکراری در رابط کاربری.
- پس از ساخت فرآیند و نسخه، شناسه‌های برگشتی نمایش داده می‌شوند تا مدیر بتواند آن‌ها را ثبت کند. ایجاد مجدد فرآیند/نسخه در همان صفحه غیرفعال است تا کلیک تکراری باعث ساخت رکورد اضافه نشود.
- کنترلر فعلی `WorkflowsController` فقط endpointهای POST برای ایجاد و انتشار دارد و endpoint خواندن فهرست/جزئیات فرآیندها، نسخه‌ها، مراحل و مسیرها ارائه نمی‌کند. بنابراین صفحه در حال حاضر ویرایش یا بازیابی فرآیندهای قبلی پس از بارگذاری مجدد را پشتیبانی نمی‌کند. برای تکمیل این قابلیت، ابتدا APIهای خواندن باید در بک‌اند اضافه شوند.
- اتصال نسخه به دسته‌بندی پس از انتشار انجام می‌شود. اگر انتشار موفق و اتصال ناموفق باشد، پیام خطا این دو وضعیت را از هم تفکیک می‌کند؛ وضعیت اتصال باید از طریق API خواندن قابل بررسی باشد.
